## 2. İncelenen, sorun bulunmayan alanlar

- **Serileştirme:** 7 nesne türünün tamamı bütün alanlarıyla kayıpsız dönüyor (yansımalı test; yeni tür eklenip
  örneği yazılmazsa test kırılıyor). Kaydet → aç → kaydet aynı dosyayı üretiyor. Base64 + SHA-256 tekilleştirme
  doğru: aynı 8 MB resim 20 kez kullanılınca tek kopya saklanıyor, kaydetme + açma < 3 sn.
- **AutoWireEngine:** Yanlış eşleşme, kesişen hatların birleşmesi, aynı cihaz pinlerinin bağlanması, nesne
  sırasına bağımlılık bulunmadı. Eşit uzaklıktaki adaylarda seçim kararlı. Kablo uçları pine tam oturuyor.
  Junction 4 kez döndürülünce bağlantılar birebir geri geliyor. Tek hatta 600 T'lik bara < 500 ms.
- **Core katmanı** WPF bağımlılığı taşımıyor (`net10.0`, `UseWPF` yok). Symbols ve Infrastructure de öyle.
- **Derleme uyarısı:** 0 (`TreatWarningsAsErrors` açık). Bilinen güvenlik açığı: 0 (PDFsharp'ın getirdiği
  `System.Security.Cryptography.Pkcs` 10.0.15'e sabitli).

## 4. Elektrik çizim özellikleri — mimari değerlendirme (henüz geliştirilmedi)

| Özellik | Mevcut destek | Gereken değişiklik |
|---|---|---|
| Genişletilebilir sembol kütüphanesi | `ISymbolCatalog` arayüzü var; semboller C# kodunda. `SymbolDefinition`/`SymbolPrimitive` JSON'a uygun (polimorfik). | JSON sembol dosyası yükleyici + birden çok katalogu birleştiren `CompositeCatalog`. **Önemli:** grafik katalogdan okunduğu için kütüphanede olmayan sembol yer tutucu çizilir; kullanılan sembol tanımları projeye de gömülmeli (EPLAN gibi). Format değişikliği gerekir. |
| Kullanıcı tanımlı sembol | Temel şekiller yeterli (çizgi, dikdörtgen, daire, yay, metin). | Sembol editörü (UI). Polyline, dolgulu şekil, metin hizalama primitifleri eksik. |
| Pin düzenleme | Her cihaz kendi `ConnectionPoints` kopyasını tutuyor (proje kütüphaneden bağımsız). | Yalnızca arayüz: pin ekle/taşı/yön/ad. |
| Referans numaralandırma | `ReferenceGenerator`: proje genelinde `-K1, -K2…` | Sayfa/kolon tabanlı tanım (`-1K3`), toplu yeniden numaralandırma, tekrar eden tanım kontrolü. |
| Kablo numaralandırma | Kablolar kalıcı değil (her seferinde hesaplanıyor). | Kablo numarası, kablonun iki pin kimliği çiftine bağlı kalıcı bir kayıt olarak tutulmalı (`WireAnnotation`). Format değişikliği. |
| Potansiyel takibi | `WireConnection` grafiği + junction'lar mevcut. | Union-find ile net çıkarımı kolay. Eksik: sembol içi iletim tanımı (klemens 1–2 iletir, kontak iletmez) → sembol modeline "internal connection" eklenmeli. |
| Kontak–bobin çapraz referansı | Cihaz tanımı (`Reference`) ve 10 kolonlu sayfa düzeni (`PageLayout`) var. | Cihaza "ana fonksiyon / yardımcı fonksiyon" bilgisi ve ortak cihaz adı; bobin altında kontak ayna tablosu çizimi. |
| Klemens planı | Klemens sembolü var; `-X1:1` adlandırması elle. | Klemens şeridi + klemens no alanları, rapor sayfası türü. |
| Kablo / bağlantı listesi | Netler çıkarılabilir. | Rapor üretici + rapor sayfası türü (`PageType.Report`) veya CSV/Excel dışa aktarma. |
| Sayfa numaralandırma | Sıra numarası, antette `n / N`. | Elle sayfa numarası, yapı tanımları (`=Tesis+Yer`). |
| Sayfalar arası referans | Yok. | Yeni nesne türü "kesme noktası" (ad + yön), aynı adlılar eşleşir, karşı sayfa/kolon yazılır. AutoWire'a pin olarak katılabilir. |

Sonuç: en çok fayda sağlayacak altyapı adımı **net (potansiyel) çıkarımı + sembol içi iletim tanımı**.
Kablo numarası, bağlantı listesi, klemens planı ve sayfalar arası referans bunun üzerine kurulur.
Sembol tanımlarının projeye gömülmesi, PDF şemalarından yapılacak sembol envanterinden **önce** kararlaştırılmalı.
